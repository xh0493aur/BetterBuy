## 一、项目名称与简介

**项目名称**：BetterBuy 智选 —— 面向大学生的 AI 理性消费与绿色消费助手

**一句话简介**：先问「该不该买」，再问「买哪一个」。

**简介（约 280 字）**

大学生买错东西的成本，往往不是多花几十块，而是一件用不上的东西在宿舍放四年。
BetterBuy 智选 是一个网页工具：粘贴一个商品链接，或者直接写一句话说明想买什么、
用来做什么、预算多少，它会给出三部分结果——一份「推荐购买 / 建议进一步比较 /
建议暂缓购买」的判断与理由；一组更省钱也更少浪费的替代路径（先修、先升级、买二手、
或者干脆不买）；以及下单前必须逐条确认的风险清单（型号是否一致、是否兼容、
评价样本是否足够、价格是否已过期）。

它不替用户下单，也不推荐特定品牌。价格、评价、参数全部来自可公开访问的官方接口与页面，
拿不到的字段直接显示「数据源未提供」，不用估算值填补。判断逻辑全部公开，
用户可以展开「查看分析依据」逐条核对，没有黑箱结论。免注册、免费、手机可用。

## 二、项目解决的社会问题

**1. 冲动消费与「促销驱动决策」**

大学生是价格敏感群体，也是最容易被「限时」「仅剩」「同学都有」影响决策的群体。
问题不在于买贵了，而在于**买错了**——买到不兼容的配件、买到用不上的东西、
买到和手上重复的东西。这类损失不会出现在任何账单上，但真实发生。

**2. 信息不对称：参数看不懂，评价分不清**

「IPS 面板」「Type-C 一线连」「额定容量」「气压棒认证」——这些参数决定了东西能不能用、
能用多久，但商品页往往只写卖点不写限制。学生只能靠销量和好评率判断，
而这两项恰恰最容易被运营。

**3. 缺少「不买」这个选项**

现有电商工具全都服务于「促成交易」：比价、领券、推荐更贵的型号。
没有任何一个环节会告诉用户「你现在这个还能修」「你手上那个其实够用」。
**理性消费最有效的建议往往是不买，但没有人提供这个建议。**

**4. 电子废弃物与不必要的资源消耗**

学生群体的换机频率不低，但很多「该换了」其实是「电池老了」「硬盘满了」「系统脏了」——
这些都可以低成本解决。缺少的不是环保意识，而是**具体该修哪里、该怎么修**的操作指引。

## 三、目标用户与使用场景

**主要用户**：在校大学生（本科 / 研究生），生活费有限、需要自己做采购决策、缺少选购经验。

**三个真实使用场景**（都已在代码中跑通，见 `reports/scenario_*.md`）：

| 场景 | 典型输入 | 用户真正的困惑 | 工具给出什么 |
|---|---|---|---|
| 数码配件 | 「我的笔记本是联想拯救者 Y7000P，想买个外接显示器，预算 1000 元，每天写代码要用」 | 我的接口够不够？1000 块够吗？ | 3 条接口确认项、预算区间判断、5 个该看的参数 |
| 学习用品 | 「下学期要用的笔记本和记号笔，预算 60 元，每天上课记笔记」 | 这些真的都要买吗？会不会买重？ | 先清点已有存量、按学期用量买而不是按促销买 |
| 修还是换 | 「我现在用的手机电池一天要充三次，想换个新的，预算 3000」 | 到底该修还是该换？ | 第一条建议是「先换电池再考虑换机」，附自查问题 |

**使用门槛**：打开网页 → 写一句话 → 点一个按钮。不需要注册、不需要填参数表、
不需要懂权重设置（高级用户才展开）。

## 四、核心功能介绍

**1. 三种输入方式，一条分析路径**

- 粘贴商品链接（Steam 商店页可直接识别价格、好评率、评价数、核心参数）
- 只写商品名称（走品类知识库）
- 直接描述需求（最推荐，信息最全）

**2. 三档购买结论，每条都可回溯**

| 结论 | 什么时候给 |
|---|---|
| 推荐购买 | 用途明确 + 预算落在合理区间 + 无实质风险 + **有真实商品数据** |
| 建议进一步比较 | 需求可能成立，但缺价格/参数/兼容性信息 |
| 建议暂缓购买 | 需求尚不明确，或冲动信号叠加（如促销话术 + 情绪化表述同时出现） |

**3. 需求理解会「说出来给你看」**

分析结果第一块就是「我是这样理解你的需求的」：品类、预算、用途、使用频率、
已有设备，以及还缺哪些信息。用户随时可以纠正——这比假装理解更可靠。

**4. 绿色消费建议：五级阶梯**

`能不能不买 → 能不能修 → 能不能升级/换配件 → 能不能买二手 → 最后才是买新的`

覆盖 14 个品类，每条建议都配一个「可以先自查」的问题，例如
「你现在不舒服的位置是腰、颈，还是尾椎？」「开机到能用要多久？换过固态吗？」

**5. 七类购买风险，不确定就写「待核实」**

型号是否一致、配置是否相同、是否与你的设备兼容、评价样本是否足够、
价格是否过期、数据来源是否可追溯、售后条件。**「待核实」不等于商品有问题**，
它只表示这个工具拿不到判断所需的信息。

**6. 保留原有比价能力**

粘贴多个链接仍可自动发现同类竞品、做价格与口碑对比、给出五类分类推荐
（性价比最优 / 规格最优 / 预算友好 / 口碑较好 / 综合最推荐）。

## 五、技术实现方案

**技术栈**：Python 3 + Streamlit + SQLite。单进程、无云依赖、无付费服务。

**分层结构**

```
app.py                    界面层（7 个标签页，只负责展示）
betterbuy/
  wise.py                 编排层：把下面所有模块串成一次分析
  intent.py               需求理解（关键词 + 正则 + 分段规则）
  catalog.py              品类知识库（14 类：参数、兼容性、绿色路径）
  ration.py              三档结论判定（判定表 + 阈值）
  green.py                绿色消费建议（五级阶梯 + 去重）
  risk.py                 七类风险核查
  recommend.py            综合评分与五类推荐（原有）
  advisor.py              商品级购买建议（原有）
  adapters/               平台适配器：Steam / 京东 / 淘宝 / 拼多多 / 通用网页
  discovery/              竞品发现：Steam 搜索页 / 电商跨平台疑似同款
  openapi/                电商开放平台客户端（签名、传输、错误分类）
  cache.py                SQLite：商品快照、价格历史、采集日志、调用配额
  zero_cost.py            零成本强制层：配额、成本清单、合规提示
```

**关键设计决策**

1. **判断逻辑与界面分离。** 所有判断在 `betterbuy/`，界面只渲染。
   好处是可以用假采集函数做离线测试——`tests/test_wise.py` 13 个用例全部不联网。
2. **字段级来源。** 每个字段挂一个 `Source`（适配器 / 访问方式 / 原始地址 / 采集时间），
   界面上可以逐字段说明「这个价格是哪来的、什么时候采的」。
3. **缺失即缺失。** 拿不到的字段进 `missing` 列表，显示「数据源未提供」，
   不填 0、不填默认值、不用示例数据。
4. **零成本是代码强制的。** 大模型路径默认禁用（即使配了密钥也不调用）；
   每个数据源有每日请求上限（合计 800 次/天），超限时请求**根本不会发出**。
5. **不绕过任何访问限制。** 只走官方公开接口与允许抓取的公开页面，遵守 robots.txt，
   同主机请求间隔 ≥ 1.2 秒，遇 401/403/429 直接报「本工具不会绕过验证码、登录或访问限制」。

**测试**：319 个自动化用例（317 通过，2 个联网用例默认跳过）。
覆盖签名算法、链接识别、字段映射、判定边界、绿色建议无量化数字、配额超限不发请求、
界面渲染 7 个标签页等。

## 六、AI 实际使用说明（这一节请重点看）

**必须说清楚：本项目当前没有调用任何大模型。** 所有「看起来像 AI」的能力，
实际实现如下——这是刻意选择，不是能力不足的遮掩。

| 功能 | 实际实现 | 技术类别 |
|---|---|---|
| 从一句话里识别品类、预算、用途、频率 | 关键词表 + 正则 + 标点分段规则 | 规则系统 |
| 区分「要买的东西」和「已经有的东西」 | 购买动词窗口 + 段内中心词判定 | 规则系统 |
| 三档购买结论 | 判定表 + 数值阈值 | 规则系统 |
| 五类商品推荐 | 加权评分 + 贝叶斯平滑（口碑） | 传统统计算法 |
| 绿色消费建议 | 品类知识库 + 阶梯排序 | 规则系统 |
| 七类风险识别 | 字段校验 + 字符串相似度（bigram Dice） | 传统算法 |
| 大模型增强（可选） | 兼容 OpenAI 的 `/chat/completions` | **默认禁用** |

**为什么不用大模型**

1. **零成本是硬约束。** 参赛与公开试用阶段，开发者支出必须为 0 元。
2. **可审计比「像 AI」更重要。** 消费决策涉及真金白银，用户需要知道「为什么给这个结论」。
   规则引擎可以逐条回溯（界面上有「查看分析依据」），模型输出不能。
3. **不能编。** 大模型容易生成看似合理但不存在的商品、价格与评价。
   本项目的底线是「拿不到就说拿不到」，规则系统天然更不容易越界。

**大模型路径保留在哪里**

`betterbuy/advisor.py` 里留有 `llm_advice()`，只有在用户**显式关闭零成本模式**
并自行配置接口后才会调用，且输出会在本地校验商品名——对不上真实商品的条目直接丢弃。
默认情况下 `llm_available()` 恒返回 `False`，有测试钉住。

**界面上怎么标注**

结论条下方固定一行：「判定方式：规则引擎（关键词 + 判定表，非大模型）」。
不使用「AI 智能分析」「大模型深度理解」这类措辞。

## 七、公益价值与绿色消费意义

**1. 把「不买」变成一个正当选项**

主流电商工具的目标是促成交易。这个工具会在合适的时候说「建议暂缓」「你手上那个还能修」。
对生活费有限的学生来说，省下的不是折扣，是一笔本来不该花的钱。

**2. 降低选购的信息门槛**

不需要懂参数，工具会告诉「这类商品该重点看什么」，并解释每个参数为什么重要、
常见的坑是什么。这是把少数人的选购经验变成公共知识。

**3. 延长电子产品使用寿命**

绿色建议的第一级永远是「能不能不买」，第二级是「能不能修」。
换电池、换耳罩、加内存、清灰换硅脂——这些具体动作能直接减少电子废弃物。

**4. 完全免费、无需注册、数据不外传**

没有账号体系，不上传任何用户数据。所有分析在本机完成（或在你部署的免费实例上完成）。
商业比价工具通常需要登录并收集行为数据，这个不需要。

**5. 公益性的诚实边界**

本项目**没有**做用户调研，**没有**统计过帮用户省了多少钱，**也不会**编造这类数字。
公益价值目前是「提供一个不被商业目标驱动的决策工具」，仅此而已。
真实效果需要用一段时间、有一定用户量之后才谈得上评估。

### 8.6 明确没有做到的事

| 没做到 | 原因 |

## 九、未来发展规划

**近期（若入选培育）**

1. **拿到电商接口权限后跑通真实调用**——代码已就位，只差密钥。这是最有价值的一步，
   因为它能把「只支持 Steam」变成「支持国内主流电商」。
2. **把判定阈值用真实用户校准。** 现在的「风险 5 分暂缓」「3 分比较」是常识设定，
   需要真实使用数据来调。
3. **扩充品类知识库**，优先补学生高频品类（台灯、充电器、运动装备、宿舍小家电）。

**中期**

4. **加一个「我已经买了」的复盘入口**：记录实际使用频率，回头验证当时的判断准不准。
   这既能改进算法，也能让用户看见自己的消费模式。
5. **校园二手流转指引**：毕业季的闲置转让是绿色消费最直接的落地场景。

**长期**

6. **把品类知识库做成可协作维护的内容**，让懂行的人（学长学姐、维修师傅）补充规则。
   这是这个项目真正的护城河——不是算法，是知识。

**不会做的事**

- 不做「猜你喜欢」式的商品推荐流
- 不接入联盟推广链接赚佣金（这会与「劝你别买」直接冲突）
- 不为了参赛加入 RAG、Agent 这类与核心价值无关的技术
